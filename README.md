# «По следам великих открытий»

Образовательное путешествие с Ломоносовым и совёнком Знайкой для детей 5–6 лет, к 315-летию со дня рождения М. В. Ломоносова. Автор — **Чернеева Т. А.**

Это подготовленная для интернета версия существующей игры из `Ломоносов-игра.zip`. Сохранены шесть станций, 13 заданий, викторина из пяти вопросов, диплом, изображения, анимация, музыка, эффекты и 116 голосовых записей. Игра запускается непосредственно в браузере, без регистрации и установки программ.

**Опубликовано 31 октября 2026 года. [Открыть игру](https://acherneev-netizen.github.io/lomonosov-game/).**

[Репозиторий проекта](https://github.com/acherneev-netizen/lomonosov-game). GitHub Pages использует GitHub Actions, ветку `main`, обязательный HTTPS и переменную `PUBLICATION_APPROVED=true`. Владелец разрешил публичную публикацию и отдельно подтвердил право распространять три портрета и встроенные записи Microsoft Irina. Все 48 облачных проверок прошли; опубликованная игра дополнительно проверена через HTTPS на экранах 1366 и 390 пикселей.

## Как открыть локально

Для быстрого просмотра откройте `index.html` двойным щелчком в современном Chrome, Edge, Firefox или Safari. Основная игра автономна; памятка находится по ссылке в нижней части страницы. Для проверки поведения сайта и сохранения результатов предпочтителен локальный HTTP-сервер:

1. Установите Python 3, если его ещё нет. При установке Windows отметьте «Add Python to PATH».
2. Откройте папку проекта в Проводнике, в адресной строке наберите `powershell` и нажмите Enter.
3. Выполните:

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

4. Откройте в браузере `http://127.0.0.1:8000/`.
5. Остановите сервер сочетанием Ctrl+C в том же окне.

Музыка включается после нажатия «Начать путешествие» или другой осознанной команды. На панели «Звук» есть отдельные регуляторы музыки, эффектов и голоса, отключение звука и уменьшение движения. При уходе на другую вкладку звук останавливается; вернувшись, нажмите «Продолжить со звуком».

Прогресс хранится в localStorage браузера без имени ребёнка. Он не отправляется на сервер. Другой браузер, устройство или домен имеют отдельные результаты. Настройки громкости и временно импортированная озвучка после перезагрузки не сохраняются — это поведение исходной игры. Чтобы сохранить свой голос, используйте кнопку скачивания в панели звука.

## Публикация на GitHub Pages

Проверенный через подключение GitHub и GitHub CLI аккаунт — `acherneev-netizen`. Репозиторий [acherneev-netizen/lomonosov-game](https://github.com/acherneev-netizen/lomonosov-game) уже создан и опубликован. Следующие шаги описывают повторное размещение с нуля; для обычных изменений используйте раздел «Как обновлять игру». На момент проверки авторизация GitHub CLI действительна; если она истечёт, потребуется повторный вход владельца.

После разрешения владельца:

1. Войдите в нужный аккаунт на GitHub.
2. Создайте новый репозиторий с именем `lomonosov-game`. Выберите Public **только после разрешения на публичность**. Не отмечайте добавление лицензии.
3. Загрузите содержимое этой папки в основную ветку `main`, включая скрытые `.github/`, `.gitignore` и `.nojekyll`. Через обычную загрузку в браузере скрытая `.github` может не попасть в репозиторий; GitHub Desktop или Git надёжнее. При первичной публикации держите `PUBLICATION_APPROVED` выключенной.
4. Откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
5. Откройте **Settings → Actions → General** и убедитесь, что GitHub Actions разрешены. При ограничении разрешённых actions разрешите используемые официальные `actions/*`.
6. Посмотрите первый запуск в **Actions → Check and deploy game**. Проверки должны завершиться успешно; публикация пока будет пропущена.
7. После подтверждения прав и разрешения владельца откройте **Settings → Secrets and variables → Actions → Variables → New repository variable**. Имя: `PUBLICATION_APPROVED`; значение: `true`. Это обычная переменная, не секрет и не токен. Она защищает от случайной первой публикации, но не ограничивает публичность уже загруженного репозитория.
8. Откройте **Actions → Check and deploy game → Run workflow → main → Run workflow**.
9. Дождитесь зелёных заданий `check` и `deploy`. Ссылка появится в задании `deploy`, в окружении `github-pages` и в **Settings → Pages**.
10. Откройте именно выданную GitHub ссылку через HTTPS в приватном окне, начните игру и проверьте звук, карту, памятку и уведомление об авторе. Только после этого считайте публикацию завершённой.

Проверенная постоянная ссылка этой игры: [https://acherneev-netizen.github.io/lomonosov-game/](https://acherneev-netizen.github.io/lomonosov-game/). При переносе в другой аккаунт используйте формат `https://<USERNAME>.github.io/lomonosov-game/`, где `USERNAME` — действительный логин нового владельца. Для собственного домена настройте его в Pages отдельно и дождитесь действительного сертификата HTTPS.

Вариант через GitHub CLI для специалиста, после разрешения владельца:

```powershell
gh auth login --hostname github.com
git init -b main
git add .
git commit -m "Prepare original Lomonosov game for GitHub Pages"
gh repo create lomonosov-game --public --source . --remote origin --push
```

Команду `gh repo create ... --public` нельзя выполнять до отдельного разрешения. Настройте Pages и переменную по шагам выше. Не вставляйте токены и пароли в файлы, команды или переписку.

## Что делает GitHub Actions

При запросе изменений и изменениях `main` workflow:

1. Проверяет существование страниц, ссылки, метаданные авторства, неизменность уведомлений и всех 119 медиаобъектов, синтаксис JavaScript.
2. Устанавливает закреплённую версию Playwright из `package-lock.json`.
3. Проходит игру в Chromium, Firefox и WebKit; проверяет касания и размеры 320, 390, 768, 1024 и 1920 пикселей.
4. Сохраняет JSON-отчёт и снимки экрана как `browser-diagnostics` на семь дней. При ошибке публикация не запускается; откройте красный шаг для журнала.
5. Копирует в `_site/` только игру, памятку, `.nojekyll` и два файла уведомлений. Служебные скрипты и отчёты не включаются в сайт.
6. Для `main`, кроме pull request, публикует сайт только при `PUBLICATION_APPROVED=true`.

Проверки выполняются на Ubuntu 24.04 с отдельным аудиоканалом PulseAudio. Дополнительно проверяется, что игра открывается даже при зависшем ответе звукового устройства. В приложении ожидание включения аудио ограничено 1,5 секундами; отсутствие звукового устройства не блокирует начало путешествия.

Права по умолчанию — только чтение содержимого. Только отдельное задание `deploy` получает `pages: write` и `id-token: write`; личные токены не используются. Workflow подготовлен по [официальной инструкции GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages). [Успешный запуск проверок и публикации](https://github.com/acherneev-netizen/lomonosov-game/actions/runs/41228916682) подтверждён.

## Как запустить проверки самостоятельно

Нужны Node.js 22 или новее, npm, Python 3.12 или новее. Установка инструментов нужна только сопровождающему проект.

```powershell
npm ci
npx playwright install chromium firefox webkit
npm run verify
$env:TEST_BROWSERS = 'chromium,firefox,webkit'
npm test
npm run stage
```

В Linux используйте `TEST_BROWSERS=chromium,firefox,webkit npm test`; для установки системных библиотек браузеров: `npx playwright install --with-deps chromium firefox webkit`.

Результаты находятся в `test-results/results.json` и PNG-файлах рядом. Для проверки в уже установленном Chrome можно указать `$env:BROWSER_CHANNEL='chrome'`; для Edge — `msedge`. В обычной среде дополнительные параметры не нужны. `BROWSER_PROFILE`, если он задан, должен указывать на отдельный тестовый профиль, а не на личный профиль браузера.

Проверить уже опубликованную версию можно командой:

```powershell
npm run check:live -- https://acherneev-netizen.github.io/lomonosov-game/
```

Она проверяет действительный HTTPS, статус 200 и совпадение файлов с локальной версией, затем открывает сайт в новом браузерном контексте, проверяет звук после нажатия, задание, сохранение прогресса, памятку, десктоп и сенсорный экран. Отчёт — `test-results/live-results.json`. При медленном соединении первый запуск большого HTML может занять до минуты; таймаут проверки учитывает это.

## Как обновлять игру

1. Сохраните копию рабочей версии.
2. Внесите изменения в `index.html` и при необходимости в `docs/index.html`. Сохраняйте авторство, уведомления и функциональность оригинала.
3. Запустите проверки и просмотрите игру на компьютере и телефоне. Если вы намеренно заменили медиаобъекты после подтверждения прав, сопровождающий должен обновить число и контрольный отпечаток медиа в `scripts/verify.py`, сверив новые файлы.
4. Создайте отдельную ветку и pull request, проверьте зелёный статус. Затем объедините изменения в `main`.
5. Если публикация уже разрешена переменной, обновление развернётся автоматически. Дождитесь `deploy` и проверьте фактическую HTTPS-ссылку.

Если изменения внесены в GitHub через браузер, обязательно дождитесь Actions. При неуспешной проверке останется предыдущая опубликованная версия. Для временной остановки будущих публикаций измените `PUBLICATION_APPROVED` на `false`. Это **не снимает уже размещённую игру с публикации**; для этого используйте Settings → Pages → Unpublish site.

## Резервное копирование

Храните исходный `Ломоносов-игра.zip` отдельно, без изменений. Для копии опубликованного кода в репозитории выберите **Code → Download ZIP**, добавьте в имя дату и сохраните на другом носителе. Для сохранения всей истории используйте GitHub Desktop или `git clone`.

Результаты детей хранятся только в браузере и в резервную копию репозитория не входят. Игра не содержит штатного экспорта этих результатов; при необходимости сохраните наблюдения педагога отдельно. Индивидуальные имена для игры не требуются.

## Как вернуться к предыдущей версии

Проще всего открыть pull request с нужным изменением на GitHub и воспользоваться **Revert**, создав обратный pull request. Проверьте его и объедините в `main`: Actions повторно опубликует восстановленный код.

Для специалиста: `git revert <SHA-коммита>` и `git push origin main`. При нескольких изменениях лучше восстановить нужные файлы из известного рабочего коммита в отдельной ветке, проверить и объединить pull request. Не используйте принудительную перезапись истории как обычный способ отката.

## Перенос на другой статический хостинг

Выполните `npm run stage`. Готовый статический сайт находится в `_site/`. Этот каталог можно разместить на Cloudflare Pages или другом статическом HTTPS-хостинге без серверного JavaScript и специальной сборки. Главная страница — `index.html`, памятка — `docs/index.html`, все ссылки относительные. Постоянная ссылка зависит от выбранного хостинга; после переноса её нужно проверить заново. Прогресс браузера между доменами автоматически не переносится.
